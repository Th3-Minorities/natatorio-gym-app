\subsection{Performance Results and Documentation}
On \texttt{main}, the backend workflow took 2 min 40 s and the frontend workflow 6 min 59 s, both passing. The local load test ran the three k6 profiles of the Testing Plan on Docker Desktop on a laptop with an Intel i7-1260P (12 cores), 15.7 GB of RAM, and Windows 11. Docker had 16 CPUs and 7.6 GB, and PHP-FPM ran with its default 5 workers. Each run started from a fresh seed with 100 members. Table~\ref{tab:load} lists the results.

Occupancy starts at 3 because the seed already has 3 people inside. Peak and stress meet all thresholds. \roundthree{Burst is an extra profile, harder than the required load of 50 and 100 Check Ins in 5 minutes, which passed.} In the burst, every member ended with exactly one session and there were no errors, but the p95 is above the 3 second threshold. The likely cause is the PHP-FPM default of 5 workers on a laptop running Docker on Windows. The team will raise the worker count and repeat the test on the CTI server. Repeating Check In for the same user returns the same session (idempotent). Location accuracy at the gym is measured for the Final report.

The tests cover the \roundthree{ten} flows in the midterm scope. Each flow test follows the steps a person takes, on the seeded data. Each path of a flow has its own browser test, written with one technique: equivalence partitions, boundary values, state transitions, error guessing, or permissions. The path tests ran on a test branch, on the same \roundthree{five devices}; a path passes when it passes on every device it runs on. Each bug they found was reported, fixed, and its path run again.
